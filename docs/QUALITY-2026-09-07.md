# Preferans quality run

Requested scope: comprehensive refactoring and QA of multiplayer, visual design,
configurable themes, interactions, engagement loops, bots, UX, and information
architecture. Work is committed in semantic chunks. This is a working coverage
ledger; an unchecked item is not a claim of quality or completion.

## Validation standard

- Render the current source through `bin/screens`; check `bin/screens-latest`
  before inspecting pixels. Record device, selected theme, state, and result.
- Exercise interaction paths in Simulator, including recovery and cancellation.
  Screenshots supplement behavioral assertions rather than replacing them.
- Keep individual UI scenarios bounded and report their phase transitions.
- Run focused regression checks for changes to state, rules, and persistence.
- Preserve saved games and seat credentials when changing appearance.
- Validate English, Ukrainian, Russian, large text, reduced motion, iPhone,
  and iPad layouts. Distinguish simulation from live service evidence.

## Initial findings

- Appearance uses a single static green palette and forces dark mode. Card backs
  and onboarding also carry independent fixed colors. Theme changes need to
  reach every surface through shared presentation state.
- Settings leads with account deletion and tracking administration; appearance
  and play preferences should be easier to find.
- Existing tests cover seeded rules, bot determinism, authoritative multiplayer,
  core table interactions, large-text layouts, and screenshot recipes. Reuse
  these lanes and expand only where the new behavior needs evidence.
- Initial sandboxed builds could not access package downloads or Xcode caches.
  The same authorized checks are being rerun with those resources available.

## Remaining release evidence

Real-device multi-account testing is separate from simulator validation. No
production deployment, store submission, or claim of release readiness is
implied by this working ledger.

## Acceptance emphasis

Complete, understandable games remain the acceptance target: start/join,
auction and defense, tricks, scoring/settlement, and rematch/leave, including
interruption and recovery. Theme counts and green fixture tests cannot replace
these outcomes. The next passes must establish independently worked scoring
examples, supported conventions and explicit ambiguities, bot decision quality
and hidden-information discipline, actual production pacing, and separate-account
client/server recovery. Human judgment of engagement remains unverified.
